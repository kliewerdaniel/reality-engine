# Reality Engine - Contributing Guidelines

Thank you for your interest in contributing to Reality Engine.

---

## 1. Getting Started

1. Fork the repository.
2. Create a branch.
3. Make changes.
4. Run the tests.
5. Commit changes.
6. Open a pull request.

---

## 2. Contribution Requirements

- All code must be covered by tests.
- All public APIs must be documented.
- All documentation must be up to date.

---

## 3. Contribution Review

Contributions will be reviewed for:

- Correctness
- Test coverage
- Documentation
- Consistency with the architecture

---

## 4. Code of Conduct

- Be respectful and inclusive.
- Focus on the evidence and the architecture.
- Do not fabricate results.
- Verify claims before reporting them.

---

## 5. Questions and Support

- Open an issue for bugs and feature requests.
- Use the documentation for guidance.
- Contact the maintainer for architectural questions.

---

## 6. Project Principles

Reality Engine is built on the following principles:

- **Local-first:** Local storage, local inference, replaceable model providers.
- **Evidence-grounded:** Evidence preservation, provenance, source independence.
- **Temporally consistent:** Valid time vs. transaction time, historical reconstruction.
- **Continuously revisable:** Revision engine, dependency-aware updates, auditability.
- **Deterministic governance:** Models propose, deterministic systems control.
- **Sovereign:** User-controlled infrastructure, no external dependencies.
