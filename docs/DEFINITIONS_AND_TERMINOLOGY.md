# Definitions and Terminology

**Reality Engine — Definitions and Terminology Reference**
**Version:** 0.1.0
**Date:** November 1, 2026

This document defines the key terms used throughout the Reality Engine specification.

---

## 1. Core Conceptual Distinctions

The following distinctions are foundational to the entire architecture. These terms must never be used interchangeably.

| Term | Definition |
|---|---|
| **Reality** | The external environment, including physical processes, human activities, institutions, economic systems, natural systems, and digital infrastructure. Reality exists independently of the system's ability to observe it. |
| **Observation** | Information obtained about external reality. Observations may originate from direct measurement, official records, research publications, news reporting, human testimony, or digital systems. Observations may be incomplete, delayed, inaccurate, contradictory, or incorrectly interpreted. |
| **Understanding** | The system's current computational representation of external reality, constructed from available observations. Understanding is provisional and revisable. It must preserve the evidence and reasoning behind its current state. |
| **Evidence** | Information supporting or challenging a claim. Evidence is distinct from the claim itself. Evidence must be preserved immutably and traceable to its source. |
| **Claim** | An assertion about the world. A claim is a factual statement that can be supported or challenged by evidence. Claims have types (Factual, Reported, Interpretive, Predictive, Normative, Hypothetical, Quantitative) that determine how they are evaluated. |
| **Hypothesis** | An explanatory model for observed events. Hypotheses propose explanations for correlations, temporal sequences, and other patterns. They are distinct from claims because they are explicitly speculative. |
| **Conclusion** | An assessment derived from available evidence. A conclusion evaluates whether a hypothesis is supported, challenged, or unresolved by current evidence. |

## 2. Time Terminology

| Term | Definition |
|---|---|
| **World time** (valid time) | The time when an event or condition occurred in the external world. |
| **Knowledge time** (transaction time) | The time when the system recorded or learned about the information. |
| **Valid from** | The start of the valid time interval during which a fact applies. |
| **Valid to** | The end of the valid time interval during which a fact applies. |
| **Recorded at** | The time when the system recorded the information. |
| **Superseded at** | The time when a version was replaced by a newer version. |
| **Historical reconstruction** | Querying the system's understanding at a specific historical knowledge time, using only information available at that time. |
| **Current understanding of past events** | The system's current interpretation of what was true at a historical time, using all available current information. |

---

## 3. Evidence and Provenance Terminology

| Term | Definition |
|---|---|
| **Source** | The origin of information (e.g., a news organization, a government agency, a research paper, a government press release). |
| **Document** | The collected material from a source (e.g., a specific article, report, or press release). |
| **Source adapter** | A component that implements a common interface for collecting information from a specific source type. |
| **Collection checkpoint** | A persisted record of a collection run's progress, allowing resumption after interruption. |
| **Content hash** | A cryptographic hash of the document content, used for identity and deduplication. |
| **Source lineage** | The graph of relationships showing how information propagated from one source to another. |
| **Observed value** | The actual measured value in an observation. |
| **Evidence status** | The assessment of whether evidence supports, challenges, or is neutral toward a claim. |
| **Source independence** | The assessment of whether information from different sources is genuinely independent or derived from a common origin. |

---

## 4. Revision Terminology

| Term | Definition |
|---|---|
| **Revision** | A controlled change to the world model in response to new evidence or corrected information. |
| **Revision proposal** | A structured proposal to change the world model, generated by intelligence agents and validated by the revision engine. |
| **Revision event** | A recorded record of a revision proposal, its validation result, and its outcome. |
| **Accepted revision** | A revision proposal that has been validated and committed to the world model. |
| **Rejected revision** | A revision proposal that was rejected by the deterministic validation logic. |
| **Revision trigger** | The observation or event that initiated a revision. |
| **Revision type** | The category of change: NEW_INFORMATION, SUPPORTED, PARTIALLY_SUPPORTED, CHALLENGED, CONTRADICTED, SUPERSEDED, WITHDRAWN, UNRESOLVED, NO_CHANGE. |
| **Dependency** | A relationship showing that a claim or hypothesis depends on another claim or observation. |
| **Directly affected claims** | Claims that are directly impacted by a new observation. |
| **Downstream hypotheses** | Hypotheses that depend on directly affected claims and may need reassessment. |
| **Invalidation** | The process of flagging a claim or hypothesis for reassessment without automatically reversing it. |
| **Rollback** | The reversal of a revision (where applicable) to a previous state. |
| **Correction** | A new event that corrects the temporal scope or content of a previous accepted revision. |
| **Revision transaction** | A transaction containing all changes from a revision proposal, committed atomically. |

## 5. Agent Terminology

| Term | Definition |
|---|---|
| **Analyst** | An agent that extracts meaning, identifies relationships, constructs interpretations, and proposes hypotheses. |
| **Skeptic** | An agent that searches for contradictions, missing evidence, alternative explanations, and unsupported assumptions. |
| **Historian** | An agent that connects current events to historical precedents and tracks how previous interpretations changed. |
| **Forecaster** | An agent that generates explicitly testable predictions and records the conditions under which they should be evaluated. |
| **Verifier** | An agent that checks source attribution, evidence relationships, temporal consistency, and schema validity. |
| **Systems Integrator** | An agent that coordinates revision proposals and updates affected world-state projections. |
| **Agent task** | A structured input to an agent, including context, instructions, and required outputs. |
| **Agent response** | A structured output from an agent, including the analysis, evidence references, and proposed changes. |

## 6. Ontology and World-Model Terminology

| Term | Definition |
|---|---|
| **Ontology** | The common set of object types, relationship types, and semantic rules shared across all domains. |
| **Domain model** | A specialized schema for a specific domain (geopolitical, economic, scientific, etc.) that shares the common ontology. |
| **Entity** | An identifiable object in the world (country, government, company, institution, person, geographic region, scientific organization, infrastructure system, technology). |
| **Entity alias** | An alternate name for an entity (translations, abbreviations, historical names). |
| **Event** | An occurrence with a start and end time (election, legislative decision, natural disaster, economic announcement, scientific discovery). |
| **Relationship** | A connection between entities, events, claims, or hypotheses. |
| **Condition** | A state or observable condition that can change over time. |
| **World state** | The complete current representation of the world: entities, state, relationships, claims, history, and uncertainty. |
| **World-state projection** | A derived snapshot of the current world state, used for querying and display. |
| **State variable** | A measurable condition in the world model. |
| **Domain** | A logical division of the world model (geopolitical, economic, financial, scientific, technological, environmental, social, security, legal, infrastructure). |

## 7. Uncertainty and Epistemic Terminology

| Term | Definition |
|---|---|
| **Epistemic dimension** | A dimension of uncertainty: source reliability, directness, corroboration, temporal validity, measurement quality, interpretation, contradiction, completeness. |
| **Confidence score** | An optional calculated estimate of the likelihood of a claim. Not a substitute for multidimensional epistemic representation. |
| **Known limitation** | A documented gap in the system's information environment (e.g., reporting delay, missing dataset, geographic coverage gap). |
| **Unknown state** | The system's representation of what it does not know: unobserved, incomplete, or undeterminable. |
| **Value of information** | An estimate of how much a specific additional observation would improve the world model. |
| **Observation priority** | A heuristic score for deciding which observations to collect: Potential Information Value × Uncertainty Reduction × Domain Relevance × Time Sensitivity ÷ Collection Cost. |

## 8. Security Terminology

| Term | Definition |
|---|---|
| **Frozen Spine** | The deterministic control plane that enforces authorization boundaries and validates all state transitions. The LLM can propose operations; the Frozen Spine controls which revisions are accepted. |
| **Authorized actor** | An entity with permission to perform an operation (e.g., the system itself, a validated agent). |
| **Operation** | A requested action (read, propose, revise). |
| **Resource** | The target of an operation (data, state, audit record). |
| **Permission** | The authorization to perform an operation on a resource. |
| **Validation result** | The outcome of deterministic validation: ACCEPT, REJECT, or NEEDS_REVIEW. |
| **Audit event** | A recorded record of a significant operation, including the actor, operation, resource, previous hash, event hash, and timestamp. |
| **Prompt injection** | Malicious input designed to hijack the system's interpretation. Treated as a data-ingestion threat, not a prompt-engineering problem. |
| **Untrusted input** | All external information: documents, websites, extracted text, and model-generated content. Never treated as executable instructions. |
| **Sandboxed document processing** | Safe handling of untrusted documents in an isolated environment. |
| **Credential isolation** | Ensuring that credentials for external systems are never exposed to model context or logs. |

## 9. Forecasting Terminology

| Term | Definition |
|---|---|
| **Forecast** | A formal prediction with an explicitly defined hypothesis, predicted outcome, probability, time horizon, and resolution criteria. |
| **Brier score** | A proper scoring rule for binary forecasts: BS = (1/N) × Σ(p_i - o_i)². |
| **Calibration** | The property of a forecasting system where predictions of a given probability occur at approximately that frequency over a large sample. |
| **Forecast correction** | A new record that revises a forecast's assumptions or probability, preserving the original published forecast. |
| **Forecast evaluation** | The application of actual outcomes to a forecast to measure accuracy. |
| **Probability** | The predicted likelihood of a specific outcome, expressed as a number between 0 and 1. |
| **Time horizon** | The period over which a forecast is evaluated. |
| **Evaluation horizon** | The period after which a forecast is checked for accuracy. |
| **Resolution criteria** | The conditions that determine whether a forecast has resolved. |
| **Observed outcome** | The actual result that occurs after the forecast's evaluation horizon. |
| **Scoring result** | The calculated accuracy metric (e.g., Brier score) for a forecast. |

## 10. Performance Terminology

| Term | Definition |
|---|---|
| **Modular monolith** | An application with internal subsystem boundaries but a single deployable unit. The initial architecture for Reality Engine. |
| **Projection** | A derived view of the world state, maintained for efficient querying and display. |
| **Event ledger** | The append-only record of all significant events (evidence, revisions, state transitions). |
| **Extraction version** | A versioned record of the extraction model, prompt, and schema version used to extract a claim or observation. |
| **Processing status** | The current state of a document or claim in the processing pipeline. |
| **Idempotency key** | A key that allows a processing operation to be safely retried without creating duplicates. |
| **Checkpoint** | A persisted record allowing recovery from a failure at a specific processing stage. |
| **Replay** | The process of rebuilding derived world-state projections from recorded events. |
| **Reproducibility** | The ability to reconstruct a conclusion or revision from recorded inputs, model configurations, and processing versions. |
| **Deterministic replay** | Replay where the recorded events are replayed with the recorded versioned logic, producing an exact reconstruction. |

---

## 11. Benchmark Terminology

| Term | Definition |
|---|---|
| **Extraction benchmark** | A test measuring the accuracy of claim and observation extraction (precision, recall, F1). |
| **Provenance benchmark** | A test measuring the percentage of claims traceable to correct original source passages. |
| **Temporal benchmark** | A test measuring the accuracy of historical reconstruction. |
| **Revision benchmark** | A test measuring the correctness of affected conclusions after a revision. |
| **Source independence benchmark** | A test measuring whether the system correctly distinguishes independent observations from syndicated reporting. |
| **Contradiction benchmark** | A test measuring the detection of genuine conflicts. |
| **Forecast benchmark** | A test measuring forecast accuracy against proper scoring rules and baseline models. |
| **Hindsight contamination test** | A test that provides historical information in chronological order and verifies that the system does not use future information. |
| **Adversarial test** | A test using deliberately difficult scenarios (false initial reports, retracted papers, conflicting datasets, incorrect entity resolution). |
| **Baseline** | A reference model (e.g., a simple statistical model, human forecasts) against which the system's performance is compared. |
